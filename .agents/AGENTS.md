
# UIデザイン・背景色のルール
- このサイトの記事本文エリア（.site-content-contain や .content-wrapper）の背景色は `#f5f7ff`（淡いブルー）である。
- そのため、記事内で「枠線なしのボックス（グルーピング）」を作る際、背景色に `#f5f7ff` を使用すると背景と同化してしまい見えなくなる（保護色になる）ため、絶対に使用しないこと。
- 背景色でグルーピングして浮かせる場合は、真っ白（`#ffffff`）を使用し、必要に応じて `box-shadow` でドロップシャドウをつけること。
- もし `#f5f7ff` をボックスの背景に使う場合は、四方を囲むごく薄いボーダー（例: `border: 1px solid #c4d2f6;` など）をセットにして視認性を確保すること。

# CSS/SCSS編集時のルール（再発防止）
- SCSSファイルを編集して特定デバイス用（PC用・SP用など）のスタイルを追加・修正する際は、現在編集しようとしている行が「どのメディアクエリの中にネストされているか（例：`@media screen and (max-width: 767px) { ... }` の中かどうか）」を、ファイル全体を見渡して親の波括弧 `{}` を辿り、必ず確認すること。
- PC用だと思い込んでSP用のメディアクエリ内に記述してしまい、PC画面に反映されないというミスを防ぐため、スコープの確認を徹底する。

# PHPファイルへのCSS直接記述の禁止
- 今後、PHPファイル（例: `front-page.php` 等）の内部に `<style>` タグを用いてCSSを直接記述することは禁止とする。
- スタイルを追加・修正する場合は、必ず該当する SCSS ファイル（`style_add.scss` など）に記述し、コンパイルして反映させること。

# 動的置換されるDOM（Lucide Icons等）に対するCSS指定のルール（再発防止）
- HTML上で `<i data-lucide="..."></i>` と記述されている Lucide Icons などの要素は、ブラウザ表示時に JavaScript によって `<i>` タグ自体が消滅し、完全に `<svg>` タグに置換される。
- そのため、CSS（SCSS）でスタイルを当てる際に `i svg` のようなネストセレクタを使用すると、実DOMに存在しないためスタイルが適用されない（デフォルトサイズ等で表示されてしまう）。
- 今後、動的に生成・置換される要素に対してスタイリングを行う際は、ソースコード上のタグではなく **ブラウザ上で最終的にレンダリングされるDOM構造（デベロッパーツール等で確認できる構造）** を前提とし、`svg` や `.lucide` クラスを直接指定すること。
